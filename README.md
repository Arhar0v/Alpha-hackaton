# ИИ-помощник для предпринимателей в Telegram

## Назначение решения:
Решение помогает предпринимателям не теряться в информационном шуме. Бот анализирует потребности пользователя и точечно рекомендует качественные курсы, статьи и материалы для развития бизнеса. Подходит как для новичков (база и основы), так и для опытных владельцев бизнеса (прокачка конкретных навыков), экономя их время на поиск нужной информации.

## Архитектура решения
1. **Клиент (Telegram-бот):**<br>
Точка входа для пользователя. Бот запускается в личных сообщениях через команду `/start`. Принимает текстовые запросы и 
команды, помогающие пользователю в достижении его целей, после чего бот возвращает сформированный ответ.
2. **Реляционная БД (PostgreSQL):**<br>
Хранит как исходные данные из предоставленной БД `alfa_course_hackathon.backup`, так и пользовательские данные в дополнительных таблицах (`users` — пользователи, `chat_history` — история чата, `tasks` — задачи, `reminders` — напоминания).
3. **Векторная БД (ChromaDB):**<br>
Является базой знаний по обучающим материалам. Формируется на основе исходной БД `alfa_course_hackathon.backup` путем векторизации текстов для последующего быстрого поиска.
4. **Векторизация и поиск (Embeddings):** 
   * Для поиска подходящих пользователю обучающих материалов дополнительно используется модель `sergeyzh/LaBSE-ru-turbo` (sentence embedding).
   * Запрос пользователя также переводится в векторное представление.
   * Поиск релевантных материалов осуществляется на основе **косинусного расстояния** между вектором запроса и векторами описаний обучающих материалов.
5. **Генерация ответа (LLM):**
   * Найденные релевантные фрагменты документов вместе с историей диалога и профилем пользователя передаются в LLM от **Groq**.
   * Модель анализирует контекст и генерирует персонализированный ответ с рекомендациями.
6. **Выдача результата:**<br>
Сформированный текст отправляется пользователю в личных сообщениях Telegram.
7. **Дополнительные функции:**
   * **Персонализация:** с помощью команды `/profile` пользователь может заполнить свой профиль (информация о бизнесе, целях и трудностях), что позволяет модели генерировать более точные и релевантные ответы.
   * **Планирование:** команды `/task_list` и `/reminder_list` позволяют пользователю вести списки дел и напоминаний. Напоминания привязываются к конкретным задачам.
   * **Рекомендации:** по команде `/study` бот подбирает и выводит индивидуальные рекомендации по обучающим материалам «Альфа-Курса».
   * **Справка:** команда `/help` выводит полный перечень доступных команд.

## Одна команда для запуска через Docker
Для сборки и запуска проекта достаточно выполнить следующую команду в корневой директории:
```bash
docker compose up --build
```

## Переменные окружения

Перед запуском необходимо создать файл `.env` и заполнить следующие переменные:
* `TG_BOT_TOKEN` — токен Telegram-бота.
* `GROQ_API_KEY` — ключ для доступа к Groq API.
* `DB_PASSWORD` — пароль от базы данных PostgreSQL.
* `DB_HOST` — хост базы данных (для Docker используется значение `db`).

## Используемые порты
В данном проекте используются стандартные настройки портов:<br>
* `5432` — PostgreSQL.
* `8000` — ChromaDB.

## Зависимости

Все зависимости проекта зафиксированы в файле `requirements.txt`.

**Ключевые библиотеки:**
* `aiogram` — фреймворк для Telegram-бота.
* `psycopg2` — драйвер для PostgreSQL.
* `sentence-transformers`, `torch`, `chromadb` — для RAG и векторного поиска.
* `openai` — клиент для работы с Groq API.
* `apscheduler`, `python-dateutil` — планировщик задач.

## Описание входных данных
**Пользовательский ввод:**
* Если сообщение начинается на символ `/`, то бот распознает данное сообщение как команду, т.е. данный текст не является контекстом для LLM.
* Если сообщение начинается не на `/`, но оно вводится в момент когда создается/редактируется задача из списка дел (таблица `tasks`), то бот не учитывает данный текст в качестве контекста для LLM.
* Во всех иных случаях ввод пользователя считывается ботом как контекст для запроса в LLM и добавляется в историю сообщений (таблица `chat_history`).

## Пошаговый сценарий проверки

Чтобы убедиться в работоспособности решения, выполните следующие шаги:

1. **Подготовка окружения** 
2. **Запуск проекта:** Выполните команду `docker compose up --build`.
3. **Тестирование в Telegram:**
   * Откройте бота и отправьте команду `/start`.
   * Введите тестовый запрос.
4. **Ожидаемый результат:** Бот должен обработать запрос , найти в базе релевантные курсы/статьи и вернуть сгенерированный ответ с рекомендациями прямо в чат.

## Известные ограничения: 
* Контекст истории формируется на основе последних `N_MSG_HISTORY = 5` пар «вопрос-ответ» из таблицы `chat_history`.
* Для генерации ответа из базы знаний извлекается не более `TOP_K = 5` наиболее релевантных фрагментов. При этом у каждого из них косинусное расстояние не должно превышать `MAX_DISTANCE = 0.6`. В противном случае контекст из базы знаний считается пустым, и бот сообщит, что не может найти ответ и вероятно задаст уточняющий вопрос.

## Использование внешних API

В соответствии с требованиями, рабочие ключи и токены **не прикладываются** к репозиторию. В коде проекта секреты считываются из переменных окружения, которые пользователь должен задать в файле `.env` (на основе шаблона `.env.example`).

**1. Telegram Bot API**
*   **Название сервиса:** Telegram
*   **Способ подключения:** Токен считывается из окружения и передается в библиотеку `aiogram` при инициализации бота.
*   **Переменная окружения:** `TG_BOT_TOKEN` (берется у официального бота `@BotFather`).

**2. Groq API (LLM)**
*   **Название сервиса:** Groq
*   **Используемая модель:** `openai/gpt-oss-120b`
*   **Способ подключения:** Используется OpenAI-совместимый клиент (библиотека `openai`).
*   **Переменная окружения:** `GROQ_API_KEY` (генерируется в личном кабинете Groq: https://console.groq.com/home).

## Стабильность работы
В связи с сетевыми особенностями и перебоями в доступе к зарубежным библиотекам (`aiogram`) и ресурсам (`Groq API`) для стабильной работы проекта может потребоваться использование VPN.
